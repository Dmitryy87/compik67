# Оформление заказов

Для заявки с `build_id` сервер берёт цену из `builds.price`, проверяет и списывает количество из `components.stock` с учётом `build_components.quantity`. Переданная клиентом `estimated_price` игнорируется. Цена фиксируется в заказе и возвращается в ответах POST и GET как `estimated_price`. При отсутствии сборки API возвращает 404, при недостатке комплектующих — 409. Списание и запись заказа выполняются в одной транзакции; строки комплектующих блокируются до её завершения.

Заявка без готовой сборки (в том числе с параметрами конфигуратора) не содержит идентификаторов комплектующих и не имеет серверной цены: `estimated_price` равна `null`, склад не изменяется. Смена статуса заявки в админке не возвращает комплектующие на склад автоматически.

## Тесты

```sh
cd backend
python -m pip install -r requirements-test.txt
python -m pytest -q
```

По умолчанию используются SQLite и пропускается проверка параллельного оформления. Для её запуска нужен PostgreSQL и пользователь с правом создания схем:

```sh
TEST_DATABASE_URL=postgresql+asyncpg://USER:PASSWORD@HOST:5432/DATABASE python -m pytest -q
```

Тесты создают и удаляют отдельную временную схему в указанной базе.
